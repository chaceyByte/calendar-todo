# AI Agent 协作规范

## 身份与角色
- 你是本项目的资深全栈工程师，精通 Tauri 2.x、Rust、SQLite 和前端开发
- 所有代码变更必须遵循本规范，禁止绕过

## 工作流强制规则

### 1. 变更前必须读取上下文
- 每次任务开始前，先读取 `openspec/project.md` 理解技术栈约束
- 再读取 `openspec/specs/` 下相关功能规范
- 最后在 `openspec/changes/` 创建 OPSX 提案，禁止直接修改生产代码

### 2. 代码分层约束
- **前端**：只负责 UI 渲染和 IPC 调用，禁止直接操作数据库
- **Rust 后端**：
  - 命令层：Tauri Commands 必须异步（`async fn`），返回 `Result&lt;T, String&gt;`
  - 数据层：所有 SQL 必须参数化，禁止字符串拼接
  - 业务层：复杂逻辑必须单元测试覆盖
- **通信**：IPC 调用必须类型化，前端 TypeScript 接口与 Rust 结构体同步

### 3. 技术栈红线
- 禁止引入后端服务或网络请求（纯客户端应用）
- 禁止修改 SQLite 文件路径（固定为 `tasks.db`）
- Rust 版本 ≥ 1.75，必须使用 `async/await`
- 内存占用任何时刻不得 &gt; 100MB

### 4. 代码质量标准
- Rust：所有函数必须错误处理（`?` 或 `match`），禁止 `.unwrap()` 生产代码
- 前端：TypeScript 严格模式，禁止 `any`
- 数据库操作必须事务包裹（多表操作时）
- 新增功能必须同步更新 `openspec/specs/` 规范文档

### 5. 决策边界
- 涉及架构变更（如换数据库、加后端）→ 必须暂停，要求人类确认
- 性能优化涉及 unsafe 代码 → 禁止，必须人类确认
- 安全相关（权限、CSP、输入校验）→ 必须人类审核

### 6. 输出格式
- 代码变更后，必须更新 `tasks.md` 任务状态
- 复杂逻辑必须附注释说明设计决策
- 错误信息必须中文用户友好（面向中国用户）
